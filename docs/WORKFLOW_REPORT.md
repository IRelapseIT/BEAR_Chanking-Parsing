# Отчёт единого конвейера: 6 ноября 2026

**Технический путь через API работает, но цель 90% не достигнута.** На фиксированной контрольной выборке автоматически успешны **10/14 — 71.43%**. Три review-случая и повреждённый PDF остались в знаменателе. Даже отдельно среди 13 корректных поддерживаемых файлов результат 10/13 (76,92%), ниже цели. Репрезентативная корпоративная выборка с пользователем ещё не согласована.

## Методика и данные

До загрузки записаны 14 случаев, SHA256, контрольные вопросы и фрагменты. Два исходных публичных документа — W3C dummy.pdf и README TypeScript; остальные — явно синтетические регрессии, включая PDF-скан и повреждённый файл. Provenance публичных файлов: [sources.json](../verification/workflow/corpus/sources.json). Конфиденциальные документы не использовались.

Успех: документ автоматически принят и активирован, контрольный ответ найден в top-5 его чанков, у выдачи присутствуют источники. Итоговые вопросы выполнены повторно **после всех загрузок на одном фиксированном активном индексе**, а не только на растущем корпусе. Порог/вопросы не подбирались под BGE-M3; неудачные файлы не исключались. Это маленькая инженерная выборка, не оценка произвольных документов компании.

## Реальные проверки

- Настоящий HTTP API → очередь → общий парсер/чанкер → **Infinity 0.0.77** → BGE-M3 → Qdrant 1.20.0 → поиск. Ручной index-вызов не выполнялся.
- Полный перезапуск собственных API/worker/модели/Qdrant: данные и поиск сохранены.
- Реально остановлены только свои Infinity и Qdrant: обновления завершились ошибкой, старое поколение осталось активным; после восстановления API retry активировал новое.
- Удаление исключило документ из поиска; oversized multipart вернул 413. Tenant/space isolation и идемпотентная повторная загрузка проверены через HTTP.
- 15 заранее известных значений табличных ячеек сверены в checkpoint; проверены код MD, PDF page/bbox и наличие source spans. Это не независимая оценка полного извлечения или произвольного порядка чтения.
- Настоящие dense-векторы: 1024 компоненты, конечные значения, единичная норма. На входе без краевых пробелов cosine с прежним проверенным локальным BGE-энкодером практически 1; на входе с краевым пробелом — 0,99992079. Подтверждена нормализация `.strip()` внутри SentenceTransformers Infinity. Модель и исходный текст BEAR не заменялись.

JSON: [API corpus](../verification/workflow/api-corpus-report.json), [отказы и векторы](../verification/workflow/faults-report.json), [извлечение](../verification/workflow/extraction-report.json), [сохранность исходников](../verification/workflow/preservation.json).

## Моки, регрессии и повторно использованные результаты

**272 passed, 1 skipped**, одно предупреждение Starlette/httpx. Пропущен прежний unit-тест tensor pooling: PyTorch отсутствует в API-окружении, поскольку установлен в отдельном Infinity-окружении. Этот тест и реальный pooling уже проверялись в сохранённой работе «ТЕСТЫ» (260 passed без skips); новый настоящий сервер дополнительно проверен реальными векторами. Пропуск не объявляется пройденным тестом.

12 новых проверок ingestion и отдельная регрессия OCR-risk используют моки для инъекции ошибок и проверки контрактов. Реальные HTTP outage/restart/corpus результаты выше независимы от этих моков. Существующие тесты leases/heartbeat/fencing выполнялись; аварийный kill worker посреди длительной задачи отдельно на реальном корпусе не имитировался. Ruff и `pip check` обоих окружений прошли.

Проверка весов и парное сравнение BGE/Qwen на 174 документах не повторялись. Сохранённый [модельный отчёт](MODEL_COMPARISON_2026-11-06.md) относится к прежнему совместимому серверу; его качество нельзя автоматически приписать Infinity. Новая оценка текущего сервера — отдельные 14 случаев выше.

## Производительность

Windows 11, CPU `Intel64 Family 6 Model 154 Stepping 3, GenuineIntel`, 12 физических / 16 логических ядер, RAM 15.70 GiB. CPU float32, Infinity batch 4, OMP 2; GPU не использовалась, VRAM не измерялась.

- Медианное время загрузка→терминальное состояние на корпусе: 1.256 с; включает очередь, подготовку и последующие стадии, а не только парсер.
- Четыре одновременных некэшированных запроса: 0.308–0.700 с каждый; повторные: 0.017–0.072 с.
- Во время обработки 33000 байт / 28 чанков: liveness 0.0015 с, некэшированный поиск 0.213 с. Это наблюдение при одной фоновой задаче, не гарантия задержки при любой нагрузке.
- Отдельный microbenchmark двух коротких документов: embedding 0.2047 с, Qdrant upsert+проверка 0.0088 с, query 0.0020 с. Это разделённые модельные/хранилищные операции; точной трассировки всех стадий каждого документа пока нет.
- RSS snapshot, MiB: {"qdrant": 87.9609375, "embedding": 3073.58203125, "api": 368.72265625, "worker": 368.375}. Это снимок, не пик памяти. Логический размер файлов Qdrant: 592.3 MiB, включая предварительно выделенные сегменты/WAL, а не только полезные векторы.

[Нагрузочные измерения](../verification/workflow/performance-report.json), [microbenchmark](../verification/workflow/stage-benchmark.json). Промышленная масштабируемость, GPU и длительный soak test не проверялись.

## Остаток и границы готовности

1. **90% не достигнуты.** Причины: DOCX с embedded image, Markdown с изображениями и OCR-скан получают review; повреждённый PDF отклонён. Ослаблять политику ради процента нельзя. Нужны согласованные реальные документы, разметка существенности объектов и отдельная проверка OCR/таблиц.
2. Критерии не доказывают полную точность исходного документа. Порядок многоколоночных страниц остаётся эвристическим; сложные PDF и DOCX могут требовать review.
3. Во время финального прогона обнаружен и исправлен обход OCR-review после успешного Docling fallback. Исходный OCR-риск теперь сохраняется независимо от выбранного парсера; добавлен unit-контроль и выполнен новый HTTP-прогон. Собственный тестовый скан со старой политикой исключён из активного поиска.
4. Docling использует ранее подготовленные внешние пути этой машины из config.local.json; перенос на другой компьютер требует отдельной подготовки этого окружения/моделей. API и настоящий Infinity установлены в самостоятельные окружения копии.
5. Длительные документы в десятки мегабайт, авария worker под нагрузкой и согласованная параллельная нагрузка компании требуют расширенной приёмки. Прямой большой HTTP-запрос проверен на отказ, рабочий длинный контроль — 33 КБ. Очередь ограничена 128, файл 50 MiB; максимальный разрешённый объём не объявляется нагрузочно проверенным.

Технический путь воспроизводим, но общая промышленная/качественная приёмка остаётся незавершённой. [Команды и ограничения форматов](WORKFLOW.md), [аудит](WORKFLOW_AUDIT.md), [изменения](WORKFLOW_CHANGES.md).
