# PDF: постраничный резерв Docling

Реализация локальная, без commit/push. Основной маршрут — прежний pdfplumber/PDFium/Tesseract. После извлечения и до чанкинга `parse_pdf` вызывает `route_pages`: оценивает страницы и при необходимости запускает отдельный Docling-процесс с `page_range=(page, page)`.

## Настройка на этой машине

Подготовлено отдельное окружение Docling 2.148.0; зависимости BEAR не заменялись. Layout/TableFormer-модели скачаны отдельно. Перед запуском Fusion-демо или Python-конвейера в том же PowerShell:

```powershell
$env:BEAR_DOCLING_PYTHON = "D:\CODEX\BEAR\upgrade\docling-venv\Scripts\python.exe"
$env:BEAR_DOCLING_ARTIFACTS = "D:\CODEX\BEAR\upgrade\docling-models"
$env:BEAR_PDF_DOCLING = "1"
```

После этого штатный Fusion PDF-маршрут использует резерв автоматически. Это настройки текущей shell-сессии, не глобальные переменные Windows. На другой машине нужны собственные пути и отдельная установка Docling 2.148.0 с предварительной загрузкой моделей; путь виртуального окружения с этой машины переносить нельзя. Для OCR нужен Tesseract с `eng` и `rus`; нестандартный исполняемый файл задаётся `BEAR_TESSERACT`.

`BEAR_PDF_DOCLING=0` отключает резерв. Без двух путей выше подозрительная страница получает `fallback_status=unavailable`, оригинал сохраняется. Основной парсер продолжает работать без установленного Docling.

В Python можно передать `FallbackPolicy(enabled=True, max_pages=8, timeout=120, max_output_bytes=33554432, ocr_min_confidence=70)` через `parse_pdf(..., policy=...)`. Можно также внедрить backend с `parse_page(path, page, context, limits)` для тестов. Лимит страниц относится к попыткам резерва на документ.

## Сигналы и выбор

Проверяются ошибки страницы, неизвестные/повреждённые символы, отклонённые табличные кандидаты, подписи таблиц без структуры, неразрешённое содержимое, неоднозначный порядок чтения, низкая уверенность OCR, короткий OCR-текст и малое количество текста рядом с крупным изображением. Это эвристики: маленькая надпись и декоративная картинка тоже могут вызвать лишнюю попытку. Они не обнаруживают все ошибки PDF.

Docling не считается правым по факту успешного запуска. Кандидат должен:

- содержать непустое текстовое содержимое и принадлежать выбранной странице;
- проходить ограничения блоков/текста, геометрии, структуры таблиц и уверенности, когда она доступна;
- сохранять все уже распознанные слова и числа с учётом количества вхождений; маркеры `(cid:N)` и replacement character исключены из сравнения;
- не иметь оставшихся признаков повреждения или неразрешённых объектов.

При исходно низкой уверенности OCR отсутствие оценки OCR у кандидата не считается улучшением. При неоднозначном порядке чтения автоматическая замена запрещена: без независимого эталона перестановка тех же слов не доказывает исправление. Сравнение слов консервативно: переносы слов или иное разбиение токенов могут отклонить полезный результат. Лингвистический смысл и правильность новых чисел оно не доказывает.

Если проверки пройдены, заменяются **все блоки страницы**. Фрагменты двух парсеров не смешиваются. Иначе исходные блоки остаются с `needs_review`. При ошибке первичного парсера доступный сырой текст сохраняется для сравнения; частично добавленные блоки откатываются, чтобы не дублировать содержимое.

## Прямой адаптер

`docling_worker.py` возвращает JSON Docling и порядок элементов `iterate_items()`. `map_docling` создаёт `ContentBlock` напрямую, без Markdown-промежуточного представления. Сохраняются версия парсера, исходная ссылка элемента, номер страницы, bbox и доступные confidence scores.

Таблицы переходят в `Cell`: текст, строка/колонка, rowspan/colspan, заголовки; дополнительно сохраняются bbox ячеек и роли column/row header. Проверяются пересечения, пропущенные ячейки и выход за объявленную сетку. Координаты BOTTOMLEFT преобразуются в PDF points TOPLEFT. Многостраничные элементы с чужой provenance отклоняются; сложные разорванные таблицы пока требуют review.

В `block.metadata.pdf_route` и предупреждениях `pdf_page_route:<JSON>` сохраняются причины, попытка резерва, выбранный парсер, остаточные проблемы и время. Исходные предупреждения не удаляются. `heuristic_checks_passed` не означает верификацию оригинала: `source_fidelity` остаётся `unverified`, граница приёмки Fusion для индексации не изменена.

## Ограничения ресурсов

По умолчанию не более 8 запусков по 120 секунд на документ; загрузки Hugging Face в worker отключены, remote services запрещены. Размер JSON проверяется перед чтением (32 MiB). Это не жёсткий предел памяти или дискового пространства процесса: ограничение ответа проверяется после записи файла, а модель загружается на каждую выбранную страницу. Большой документ всё равно открывается Docling, хотя ML-конвертация ограничена `page_range`. Прогретый сервис или пакетная обработка выбранных страниц могут уменьшить накладные расходы в следующей итерации.

## Проверка

```powershell
python -m pytest bear-text-beta/tests bear-fusion-lab/tests -q
python verification/pdf_fallback_smoke.py --python <docling-python> --artifacts <models> --output <results>
python verification/pdf_fallback_smoke.py --python <docling-python> --artifacts <models> --output <control-results> --ruled-control
```

Smoke использует настоящий Docling и локальный токенизатор E5. Он генерирует двухстраничный PDF с известными 12 значениями, проверяет сохранение первой страницы, постраничный запуск и последующий чанкинг. `--ruled-control` добавляет явную сетку и **намеренно подменяет отказ основного табличного извлечения только в процессе smoke**, чтобы проверить положительный путь. Рабочий парсер этим режимом не изменяется.

На PDF без рамок Docling тоже не восстановил таблицу: замена отклонена, страница осталась `needs_review`. На контроле с сеткой перенесены 12/12 ячеек; чанкинг и проверка покрытия прошли. Это два синтетических случая, не доказательство улучшения качества на произвольном корпусе. Для следующей приёмки нужен набор реальных размеченных PDF с колонками, сканами, повреждёнными шрифтами и многостраничными таблицами.

Артефакты: [полный вывод тестов](../verification/pdf-fallback/tests.log), [отчёт безрамочной таблицы](../verification/pdf-fallback/borderless/report.json), [положительный контроль](../verification/pdf-fallback/control/report.json). В JSON указаны время основного/резервного пути, причины решения, реальные блоки и результаты чанкинга. Обнаружение 12/12 здесь означает совпадение текстов ячеек с заданной таблицей, а не оценку на реальном документном корпусе.
