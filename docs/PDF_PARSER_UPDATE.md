# Обновление PDF-парсера в BEAR

В этой ветке полный конвейер BEAR вызывает обновлённый PDF-парсер через штатный реестр. Результат разбора по-прежнему использует `ParsedDocument v1`. Разметка таблиц хранится в метаданных блоков и используется при построении чанков.

## Что изменилось

- **Выбор обработки по странице и полю.** pdfplumber читает пригодный текстовый слой и векторную геометрию. Tesseract обрабатывает скан или область без пригодного текста. Docling получает отдельную страницу при проблеме структуры, а его ячейки повторно сверяются с координатами исходного текста. PaddleOCR по умолчанию перепроверяет вырезки с возможным пропуском поля, низкой уверенностью или несоответствием формату. Пересекающиеся вырезки объединяются, обязательные поля получают бюджет первыми.
- **Единая модель таблицы.** Векторная сетка берётся из pdfplumber, прямая сетка на растре ищется через Pillow, а границы простой безрамочной таблицы восстанавливаются по общим пробелам между столбцами. Пустые ячейки и объединения остаются в сетке. Слово, которое нельзя однозначно привязать к одной ячейке, приводит к ручной проверке.
- **Заголовки доходят до чанков.** `cell_bboxes` описывает границы ячеек, `cell_content_bboxes` — прочитанный текст внутри них, а `cell_header_links` хранит идентификаторы заголовков столбца и подписей строки. Например, значение `180` получает строку `2025` и столбец `Revenue USD`. При многоуровневой шапке сохраняется путь от общего заголовка к частному. Чанкер и проверка чанков используют эти связи, а при отсутствии однозначного заголовка остаётся номер колонки.
- **Сохранена ручная приёмка.** Неоднозначные области, обязательные пустые поля, OCR-конфликты и восстановленные реквизиты требуют сверки. Результат OCR и границы таблицы сами по себе не удостоверяют правильность документа.

## Проверка на публикационной копии

Один синтетический PDF из шести страниц содержит текст, пустую страницу, полный скан, смешанную страницу и две безрамочные таблицы. В одном столбце значение намеренно сдвинуто на 24 пункта. Предыдущий замер дал 6 из 12 верных связей. В этом замере скрипт проверяет идентификаторы из `cell_header_links`, включая строку, заголовок столбца и значение.

| Режим | Верные связи | Ошибочные связи | Правильные исходы по полям | Tesseract / PaddleOCR / Docling | Время одного прогона |
| --- | ---: | ---: | ---: | ---: | ---: |
| Без второго OCR | 12/12 | 0 | 2/3 | 2 / 0 / 0 | 0,76 с |
| Сплошная перепроверка | 12/12 | 0 | 2/3 | 2 / 1 / 0 | 25,35 с |
| Выборочная перепроверка | 12/12 | 0 | 3/3 | 2 / 1 / 0 | 6,68 с |

В метрику полей входит одно заведомо пустое поле. Выборочная перепроверка восстановила `-125.50 USD` и оставила отметку для сверки. Вызов Docling на этих шести страницах не понадобился. Времена включают запуск воркеров и относятся к одному локальному прогону.

Полная регрессия ядра и Fusion на Windows с Python 3.12 и локальным токенизатором BGE-M3 дала **302 успешных теста и 1 пропуск**. Пропущен тест локального инференса из-за отсутствия PyTorch в API-окружении. Сервисы Infinity и Qdrant заново в рамках этой публикации не прогонялись.

Отдельный контроль с реальным Docling имитировал отказ первичного извлечения на странице с сеткой. Первая страница осталась на основном маршруте, вторую обработал Docling. В таблице сохранились 12 из 12 значений, 7 чанков прошли проверку.

Регрессии проверяют таблицу с объединённой шапкой, пустую ячейку, неоднозначное пересечение границы, смещение числа, масштаб и поворот координат, поле с конфликтом знака и ограничения OCR. Тест прямой сетки на растровом PDF использует реальный Tesseract и сохраняет статус `needs_review`.

## Воспроизведение

Установите API-окружение из [главного README](../README.md) и тестовые зависимости. Пути к моделям и окружениям в публикуемой конфигурации пустые. Для сервисов заполните `docling_python` и `docling_artifacts` или `paddle_python` и `paddle_models` в `config.local.json`. Для PaddleOCR используется отдельное окружение с [requirements-paddle-ocr.txt](../requirements-paddle-ocr.txt), локальными моделями `PP-OCRv5_mobile_det` и `eslav_PP-OCRv5_mobile_rec`. Для Docling требуются локальные артефакты разметки и TableFormer. Прямой запуск проверок использует переменные `BEAR_PADDLE_PYTHON`, `BEAR_PADDLE_MODELS`, `BEAR_DOCLING_PYTHON` и `BEAR_DOCLING_ARTIFACTS`.

```powershell
./.venv/Scripts/python.exe -m pytest bear-text-beta/tests bear-fusion-lab/tests -q
./.venv/Scripts/python.exe verification/pdf_table_benchmark.py artifacts/pdf-table-benchmark
```

Для тестов с локальным токенизатором задайте `BEAR_TEST_TOKENIZER` путём к подготовленной модели. Вызов Docling при структурном сбое отдельно проверяет `verification/pdf_fallback_smoke.py --ruled-control` с путями к окружению, моделям и токенизатору. Скрипт сравнения записывает синтетический PDF и JSON с маршрутами и замерами в указанный каталог. Результаты относятся к выбранным примерам. Наклонённые сканы, разорванные линии, сложные безрамочные и многостраничные таблицы требуют отдельной приёмки.
