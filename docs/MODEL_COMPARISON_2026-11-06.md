# Qwen3 и BGE-M3 в BEAR: реальные проверки 06.11.2026

**По полноте поиска небольшой перевес у Qwen3-Embedding-0.6B; на CPU BGE-M3
быстрее и расходует меньше памяти. Обе модели технически работают корректно.**
На первом месте правильный документ найден одинаково часто. Исходную рабочую
папку я не изменял; доработки внесены только в `BEAR_BGE_M3`.

Рекомендация: пока сохранить Qwen3 как исходный вариант с приоритетом полноты
поиска, а исправленную BGE-копию использовать как рабочую альтернативу для CPU.
Данных недостаточно, чтобы объявлять одну модель лучшей для любых корпоративных
документов или менять основной вариант только по этому небольшому корпусу.

## Что именно сравнивалось

| Свойство | Qwen3 | BGE-M3 |
|---|---|---|
| Модель | `Qwen/Qwen3-Embedding-0.6B` | `BAAI/bge-m3` |
| Ревизия | `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3` | `5617a9f61b028005a4858fdac845db406aefb181` |
| Получение dense-вектора | Последний значимый токен с учётом padding | Первый CLS-токен |
| Размерность в проверке | 1024 | 1024 |
| Инструкция перед запросом | Английский `Instruct: … Query:` из рабочего Qwen-smoke | Не добавляется |
| Префикс перед документом | Пустой | Пустой |
| Максимальный контекст по карточке модели | 32K | 8192 |
| Фактический предел данного стека | Профиль 512, HTTP-провайдер 480 | Профиль 512, HTTP-провайдер 480 |

Карточки разработчиков: [Qwen3](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B),
[BGE-M3](https://huggingface.co/BAAI/bge-m3). Контекст модели не означает,
что текущий BEAR автоматически использует весь этот объём: рабочий целевой
размер чанка остаётся 320 токенов. Полные контексты 8K/32K здесь не испытывались.

Принадлежность к папке «Qwen» сама по себе не определяет активную модель.
В исходной папке defaults до сих пор указывают на E5. Поэтому для сравнения
создан явный закреплённый профиль Qwen3 по существующему рабочему smoke-сценарию.
Неявного сравнения E5 с BGE не было. В BGE-копии профиль загружался из её
реального `models/bge-m3/bear-model.json`.

У BGE-M3 также есть sparse и multi-vector возможности. В этом опыте использовался
только dense-путь, как и у Qwen3. Файлы дополнительных голов на диске сами по себе
не включают гибридный поиск. Реранкер и RRF не использовались.

Контрольные суммы обоих файлов весов совпали с LFS SHA256 официальных
закреплённых ревизий Hugging Face. Файл BGE-M3 не повреждён и соответствует
заявленным весам. Инференс использовал настоящие веса, без случайных или
заглушечных векторов. Результаты: `weights-verified.json`.

## Методика

Один и тот же CPU, Python 3.12.14, PyTorch 2.8.0+cpu, transformers 4.57.6,
Chonkie 1.7.0. Вычисления float32, 4 потока, HTTP batch до 16,
внутренний microbatch 4. Запуски моделей последовательные.
На компьютере есть RTX 2050, но установленный для этого теста PyTorch работает
на CPU. GPU, fp16, квантование и серверный пакет Infinity не проверялись.
Использовался локальный совместимый HTTP-сервер с правильным pooling для каждой модели.

Общий корпус: **174 документа, 66 запросов, 288 одинаковых исходных фрагментов**.
Совпадение фрагментов двух прогонов проверено программно. Каждый помещается
в 320 токенов обоих токенизаторов. Ничего не обрезалось. Пределы учитывают
специальные токены и добавляемую инструкцию запроса.

- 40 запросов из тестовой части SciFact и 148 научных документов: все релевантные
  источники выбранных запросов, до двух трудных BM25-конкурентов на запрос и
  24 случайных отвлекающих документа. Выборка зафиксирована seed `20261106`.
- 26 явно вымышленных контрольных документов и запросов: 17 русских, 5 английских,
  4 межъязыковых. Проверяются сроки, единицы измерения, годы/числа, похожие
  условия, пути файлов и поведение кода Go. Несколько допустимых ответных
  документов учитываются в разметке.

SciFact получен по [официальному примеру BEIR](https://github.com/beir-cellar/beir#-quick-example).
Это уменьшенный пул кандидатов, **не полный BEIR/MTEB benchmark**. Варианты
корпуса, вопросы и SHA256 сохранены до сравнения. Порог или инструкции не
подбирались по ответам одной модели.

Поиск — точное cosine-сходство настоящих нормализованных векторов.
Если документ разделён на несколько фрагментов, его оценка равна максимуму
оценок фрагментов; выдача содержит уникальные документы. Это отделяет качество
эмбеддингов от различий автоматического чанкинга.

## Качество поиска

| Метрика | Qwen3 | BGE-M3 |
|---|---:|---:|
| Правильный источник первым, Hit@1 | **51/66 — 77.27%** | **51/66 — 77.27%** |
| Хотя бы один правильный источник в top-5, Hit@5 | **63/66 — 95.45%** | 61/66 — 92.42% |
| Средняя полнота релевантных источников, Recall@5 | **95.15%** | 91.82% |
| MRR@10 | **0.8597** | 0.8434 |
| nDCG@10 | **0.8901** | 0.8644 |

Hit@5 отвечает на вопрос «нашёлся ли хотя бы один нужный документ в пятёрке».
Recall@5 учитывает все размеченные релевантные документы. MRR выше, когда первый
правильный источник находится ближе к началу выдачи; nDCG учитывает размещение
нескольких релевантных источников. Это метрики retrieval, не точность готовых
ответов LLM: генератор ответов в проверке отсутствует.

| Группа | Qwen3: Hit@1 / Hit@5 | BGE-M3: Hit@1 / Hit@5 |
|---|---:|---:|
| SciFact, 40 запросов | 27/40 / **37/40** | 27/40 / 35/40 |
| Русские контроли, 17 | 15/17 / 17/17 | 15/17 / 17/17 |
| Английские контроли, 5 | 5/5 / 5/5 | 5/5 / 5/5 |
| Межъязыковые, 4 | 4/4 / 4/4 | 4/4 / 4/4 |

По Hit@1 модели не просто нашли одни и те же 51 вопрос: 47 успехов общие,
ещё 4 вопроса лучше решила каждая модель. По Hit@5 Qwen нашла два дополнительных
источника; случая «BGE нашла в пятёрке, а Qwen не нашла» на этой выборке нет.
Преимущество небольшое и относится главным образом к английской научной части.
Русских и межъязыковых примеров мало для общего вывода о всех документах компании.

Конкретные расхождения:

- Запрос об архивном восстановлении: BGE поставила первым правило восстановления
  основного хранилища, Qwen выбрала правильное архивное правило.
- Запрос о Go-сортировке на месте: Qwen поставила первой сортировку копии,
  BGE выбрала правильную функцию, меняющую исходный срез.
- Запрос о выручке 2025 года при определённых затратах: обе сначала выбрали
  похожую строку с другими значениями. Правильный источник у обеих был вторым.

Такие ошибки нельзя исправить заменой CLS на mean pooling или перестановкой
префиксов. Проверенный dense-инференс уже корректен. Для дальнейшего улучшения
поиска нужны отдельные испытания реранжирования, гибридного поиска и более
широкий размеченный корпоративный корпус. Гарантий, что они устранят любую
ошибку с числами или отрицанием, этот тест не даёт.

## Скорость и память

| Измерение | Qwen3 | BGE-M3 |
|---|---:|---:|
| Векторизация тех же 288 фрагментов | 277.43 с | **225.34 с** |
| Векторизация всех 66 запросов батчами | 10.61 с | **5.03 с** |
| Пиковый RSS процесса теста, МиБ | 3579.96 | **2939.05** |
| Фактически обработано токенов, документы + запросы | 57 427 | 62 156 |

Здесь BGE обработала корпус примерно на 18.8% быстрее и заняла на 17.9% меньше
пикового RSS. Память включает модель и процесс сравнения. RSS отслеживался с
интервалом 0.1 секунды. Время загрузки модели в показатели векторизации не входит.
Время запросов — весь batch-набор, не задержка одного интерактивного запроса.
Одни и те же символы дают разное число токенов, что нормально.

Это один последовательный прогон на данном ноутбуке при ограниченной свободной
памяти; результаты не являются универсальными показателями GPU/сервера и не
заменяют нагрузочный тест.

## Семантический чанкинг и полный путь BEAR

Восемь документов прошли каждую сборку через её настоящий `Services`:
TXT, Markdown с таблицей, Markdown с кодом, HTML, Unicode/emoji и связный текст.
Результаты записаны в настоящий отдельный native Qdrant. Проверены:

- целая короткая строка таблицы и полный токенный бюджет;
- поиск нужного источника и изоляция tenant/Space;
- сохранение старого поколения при намеренном отказе записи;
- активация новой версии после retry;
- отказ oversized-входа до HTTP-инференса;
- отказ сервера на запрос другой модели даже при одинаковых 1024 измерениях;
- единичная норма и совпадение одиночного и batch-кодирования с точностью float32.

Текстовые блоки парсинга совпали в 8 из 8 парных документов. Модели не заменяют
парсеры PDF/DOCX или OCR. Новый парный PDF/OCR benchmark в эту задачу не входил;
смена embedding-модели сама по себе не исправляет ошибки распознавания.

Токенизатор влияет на автоматический маршрут: один контрольный текст занял
287 BGE-токенов и сохранился целиком, а у Qwen превысил цель и дал 7 семантических
чанков. Поэтому после смены модели требуется новая обработка и индексация;
одинаковая размерность не разрешает смешивать старые и новые векторы.

Дополнительно выполнены 6 вариантов на каждую модель: длинные RU/EN тексты в
режимах adaptive, semantic и token. Обе настоящие семантические ветви выполняли
инференс, сохраняли источники, укладывались в бюджет и не уходили в резерв.
На длинном русском примере BGE дала 22 семантических чанка, Qwen — 18;
на английском — по 18. Утверждать, что одна нарезка смыслово лучше, без разметки
границ и отдельных retrieval-вопросов нельзя. Обе нарезки довольно мелкие;
параметры требуют оценки на ваших документах, а не переноса порогов по названию модели.

Проверка длинного предложения требовала сохранности и соблюдения лимита,
а не обязательного перехода в резерв: библиотека может вернуть результат,
который затем безопасно исправляет BEAR. При отдельном намеренном HTTP 500
обе сборки автоматически перешли на recursive и сохранили текст. Ошибки
`Controlled HTTP inference outage` в журнале этого опыта ожидаемы.

## Что доработано в BEAR_BGE_M3

1. Добавлен `bear-text-beta/src/bear_text_beta/local_inference.py`:
   настоящий CPU-инференс по локальным весам, правильный CLS/last pooling,
   нормализация, проверка архитектуры и размерности, запрет усечения,
   контроль batch, проверка model ID. Клиент добавляет префиксы один раз;
   сервер повторно их не добавляет. Это локальный сервер разработки,
   не серверный пакет Infinity.
2. Добавлен `start-embedding.ps1`, отдельная зависимость `local-inference`
   и четыре теста нового сервера.
3. Приведено в соответствие ожидание имени BGE-коллекции после копирования.
   BGE сохраняет `bear_bge_m3_<profile_id>`; другие явно подключённые модели
   получают общее `bear_text_<profile_id>`. Добавлена проверка Qwen-профиля.
4. Проверены исходные веса; повторная загрузка или изменение весов не потребовались.
5. Добавлены результаты и инструкции запуска. Парсеры и алгоритмы чанкинга
   не переписывались без доказанной необходимости.

До исправления: 254 теста прошли, один выявил старое ожидание имени коллекции.
После: **260 passed, без пропусков**, с реальным токенизатором BGE.
Ruff изменённых Python-файлов — без ошибок. Есть прежнее предупреждение
Starlette/httpx; оно не является ошибкой модели.

Именно установленный модуль сервера дополнительно запускался отдельным процессом:
прошли настоящий HTTP-инференс, проверка нормы, 1024 компонентов и отказа на Qwen ID.
Тестовые серверы моделей и Qdrant завершены. Исходные Python-файлы рабочей
`BEAR_Chanking-Parsing` повторно сверены по SHA256 и остались неизменными.

## Запуск BGE-сервера

Вариант установки отдельного окружения Python 3.12:

```powershell
py -3.12 -m venv .venv
./.venv/Scripts/python.exe -m pip install -c constraints-py312-tested.txt -e './bear-text-beta[dev,local-inference]' -e './bear-fusion-lab[demo,acceptance]'
./start-embedding.ps1 -Python './.venv/Scripts/python.exe'
```

Требуется доступный Python 3.12 в Windows launcher `py`. Полная установка
с нуля этими командами в данном опыте не выполнялась; проверка использовала
существующее окружение и ML-dependencies этого компьютера.

Проверенный путь запуска на данном компьютере, без установки новой `.venv`:

```powershell
cd 'D:\CODEX\BEAR\BEAR_BGE_M3'
$env:PYTHONPATH='D:\CODEX\BEAR\upgrade\embedding-ml'
./start-embedding.ps1 -Python 'D:\CODEX\BEAR\upgrade\.venv\Scripts\python.exe'
```

Сервер слушает `127.0.0.1:7998`, веса не скачивает. Если порт занят, запуск
завершается ошибкой и не останавливает чужой процесс. Остановка — Ctrl+C.
Для приложения в другом окне выполните `. ./use-bge-m3.ps1`.
Для индексации и поиска также нужен Qdrant на указанном в настройках адресе;
скрипт запуска модели не запускает Qdrant или API автоматически.

Подробные данные находятся в `verification/model-comparison/`:
`bge/report.json`, `qwen/report.json`, `semantic-report.json` внутри каждого
каталога модели, разметка `corpus.json`, контрольные суммы весов,
`regression-final.xml`, `installed-server-report.json` и скрипты воспроизведения.
Внутри каталога есть README с точными командами сравнения.
