# Единый локальный конвейер BGE-M3

Рабочая копия — `BEAR_BGE_M3`. Основной `BEAR_Chanking-Parsing` не изменялся. Сравнение моделей и проверка весов из чата «ТЕСТЫ» сохранены; повторное сравнение 174 документов не запускалось. Новый результат относится к настоящему **Infinity 0.0.77**, а не к прежнему совместимому локальному серверу.

## Запуск и остановка

На этой машине подготовлены `.venv` (Python 3.12.14, API/парсеры) и `.infinity-venv` (Infinity, CPU PyTorch 2.8.0). Окружения основной версии не менялись. NumPy ядра — 2.5.4, Infinity — 1.26.4: они намеренно разделены.

```powershell
cd D:\CODEX\BEAR\BEAR_BGE_M3
./.venv/Scripts/python.exe scripts/services.py start
./.venv/Scripts/python.exe scripts/services.py status
./.venv/Scripts/python.exe scripts/services.py stop
```

Повторный `start` при существующем реестре не перезапускает процессы автоматически. Реестр — `runtime/processes.json`; остановка проверяет PID, время создания и командную строку, завершает только свои процессы и их потомков. Занятый порт приводит к отказу запуска, а не к остановке чужого сервера. При аварии launcher используйте `status`, проверьте свои процессы и выполните `stop`.

Адреса из `config.local.json`: API `http://127.0.0.1:8002`, Infinity `http://127.0.0.1:7998/v1`, Qdrant `http://127.0.0.1:6335`; grpc Qdrant — 6336. Слушают только localhost. Swagger API: `/docs`, готовность: `/ready?capability=index`, liveness: `/live`. Готовность зависимостей не заменяет контроль живого worker через реестр/логи.

Хранение постоянное: `state-bge-m3/objects`, `state-bge-m3/manifest.sqlite3`, `runtime/qdrant-storage`. Остановка не удаляет данные. Коллекция `bear_bge_m3_workflow_v1`, cosine, 1024 компоненты. Не направляйте её на прежние векторы другой модели/сервера.

Для повторной установки нужен доступный Python 3.12:

```powershell
./setup-workflow.ps1 -Python <путь-к-python-3.12.exe> -DownloadQdrant
```

`requirements-workflow-api.txt` и `requirements-workflow-infinity.txt` фиксируют наблюдённые версии. Qdrant 1.20.0 скачивается только с явным `-DownloadQdrant`; архив проверяется SHA256. Веса BGE-M3 отдельно должны находиться в `models/bge-m3`, ревизия `5617a9f61b028005a4858fdac845db406aefb181`. Скрипт не скачивает веса автоматически. Модель ранее сверена с официальным LFS SHA256, результат сохранён в `verification/model-comparison/weights-verified.json`.

Docling использует уже подготовленное независимое окружение и локальные модели по двум путям в `config.local.json` (`docling_python`, `docling_artifacts`). Это переиспользованный ресурс этой машины **вне копии**, а не новая чистая установка Docling. Его пакеты и модели не изменялись. На другом компьютере нужно отдельно подготовить Docling 2.148.0 и изменить пути; пустые пути отключают конфигурацию резерва и оставляют подозрительные страницы в review. Подробности — [PDF fallback](pdf-fallback.md). Для OCR системно нужен Tesseract с `eng` и `rus`.

В Git опубликован переносимый шаблон с пустыми Docling-путями: настройте их для своей машины. Исторические абсолютные пути в отчётах описывают среду измерений. `workflow_preservation.py` предназначен для исходного рабочего пространства с сохранённой основной копией, а не для проверки чистого клона.

## Загрузка и поиск

```powershell
$ctx = @{tenant_id='company'; space_id='manuals'; document_id='policy'; document_version=1; filename='policy.pdf'} | ConvertTo-Json -Compress
$job = Invoke-RestMethod 'http://127.0.0.1:8002/v1/documents' -Method Post -Form @{file=(Get-Item './policy.pdf'); context=$ctx}
Invoke-RestMethod "http://127.0.0.1:8002/v1/jobs/$($job.job_id)"
$query = @{query='Каков срок возврата?'; tenant_id='company'; space_id='manuals'; top_k=5} | ConvertTo-Json
Invoke-RestMethod 'http://127.0.0.1:8002/v1/search' -Method Post -ContentType 'application/json' -Body $query
```

Загрузка возвращает HTTP 202. Отдельный вызов `index` не нужен: worker сам выполняет парсинг, чанкинг, приёмку, embedding и индексацию. Состояния: `queued`, `parsing`, `chunking`, `embedding`, `indexing`, `searchable`, `needs_review`, `failed`; удалённый документ отображается `deleted`. Полный результат с блоками, ячейками и предупреждениями: `GET /v1/jobs/{id}/result`.

Повтор идентичной загрузки возвращает тот же job ID, лишняя копия оригинала удаляется. Версия документа неизменяема: другое содержимое требует увеличения `document_version`. `POST /v1/jobs/{id}/retry` повторяет остановившееся задание; активное задание повторно не запускается. Старый результат доступен до полной записи, проверки и активации нового. Lease и желаемое поколение проверяются также при начале индексации и активации. Устаревший worker не получает право переключить активный индекс.

Удаление: `DELETE /v1/documents/{document_id}?tenant_id=company&space_id=manuals`. Сначала документ исключается из активного поиска, затем очищаются векторы; при ошибке очистки возвращается `cleanup_pending`. Оригинал и история сохраняются. Восстановление удалённого ID отдельной операцией пока не реализовано.

## Форматы и приёмка

| Формат | Рабочий API-маршрут | Ограничения |
| --- | --- | --- |
| TXT | Нативное декодирование, абзацы и строки | UTF-8/BOM; CP1251 только при разрешении. Не поддерживаются произвольные бинарные данные. |
| MD | StructuredMarkdownParser и канонические таблицы Fusion | Код сохраняется; include не раскрывается; изображения могут дать частичный результат/review. |
| HTML/HTM | Нативный DOM-парсер и TableProcessor | Скрипты не исполняются, удалённые ресурсы не скачиваются; визуальное содержимое может требовать review. |
| DOCX | Нативный OOXML в API: заголовки, списки, body, таблицы, колонтитулы | Ячейки восстанавливаются через существующий `restore_docx_tables`; объединения и длинные значения проходят валидатор. Изображения/OLE, формулы, tracked changes, сноски и другие отмеченные части требуют review. Нумерация списков не вычисляется как Word, номер страницы неизвестен. Сложные вложенные таблицы могут быть отклонены. |
| PDF с текстом | Существующий Fusion PDF CPU adapter через общий ParsingPipeline | Порядок чтения эвристический; неоднозначные страницы направляются в резерв/review. |
| PDF-скан | PDFium + Tesseract, при проблемах Docling | OCR с числовыми данными или неразрешённым содержимым не принимается автоматически этой политикой. |

Поддержка DOCX в API не требует отдельного Dedoc-сервиса. Старый внешний Dedoc-маршрут Fusion-демо оставлен как отдельный экспериментальный путь. XLSX/PPTX/DOC/архивы не заявлены.

Политика `operational-v1` отличает техническую завершённость, частичное извлечение и допуск к автоматической индексации. Полное покрытие чанками проверяется независимо от полноты парсинга. Неразрешённые блоки, partial, подозрительные PDF, неподдержанные объекты и OCR получают `needs_review`, пустой результат — отказ. Обычный результат без этих признаков принимается автоматически. `source_fidelity` при этом остаётся `unverified`: это не независимый аудит оригинала. Приёмка хранится в checkpoint и payload; индексатор запрещает результат с явным отказом политики.

Выдача содержит текст, документ/версию, раздел, source spans, доступные страницы/bbox и ограничения приёмки. Авторизация не реализуется: tenant/space — контракт доверенного контекста за внешним gateway, а не самостоятельная защита от подделки контекста клиентом.

## Embedding и ресурсы

BGE-M3 использует CLS pooling, dense 1024, пустые модельные префиксы; E5/Qwen-инструкции не добавляются. Полный токенный бюджет учитывает контекст и special tokens: target 320, max 480, профиль 512. Превышение отклоняется клиентом до HTTP, чанкер не обрезает исходник молча. Сам отдельный Infinity endpoint не является границей лимитов публичного API: его прямые клиенты должны соблюдать этот контракт.

SentenceTransformers 3.4.1 внутри Infinity удаляет пробелы **по краям** входа перед токенизацией. Это подтверждено парным запросом. Исходные `Chunk.text`, `embedding_text` и источники BEAR не меняются. Векторы прежнего собственного сервера и Infinity нельзя объявлять побитово одинаковыми или смешивать без отдельного испытания; измеренное расхождение и причины — в отчёте. Кэш в памяти процесса, ключ включает профиль, назначение и текст; после перезапуска пуст.

Один worker, максимум 128 незавершённых заданий, файл до 50 MiB, multipart до 51 MiB. Сервер Infinity batch 4, CPU float32, 2 OMP-потока; BetterTransformer и тяжёлый warmup отключены. API и worker разнесены по процессам. Запросы одного `EmbeddingPipeline` сериализуются: промышленная масштабируемость не заявляется. SQLite хранит локальные jobs/leases/checkpoints; Redis/LLM/reranker/sparse не добавлены.

Не запускайте их при текущих пользовательских загрузках. Корпус содержит публичные файлы с provenance и явно синтетические контроли; реальные конфиденциальные документы не использовались.
