## Почему изменился DOCX-парсер

В общем API внешний Dedoc заменён нативным OOXML для воспроизводимого минимального
запуска без обязательного отдельного Dedoc-процесса. Это эксплуатационное упрощение,
а не доказанное улучшение извлечения. Экспериментальный Dedoc-путь Fusion остался.
Текущая реализация поэтому расходится с прежним решением «Dedoc основной»;
эквивалентность сложных DOCX не доказана.

Найден конкретный недостаток нативного обхода: верхний цикл видел только p/tbl,
но мог пропустить текст и таблицы внутри стандартных sdt/content controls.
Исправлено: ограниченный рекурсивный обход sdtContent/customXml с сохранением
порядка и пути источника; неизвестный body-контейнер отмечается предупреждением.
В ячейках таблиц добавлен аналогичный обход, служебные bookmark-маркеры допустимы.
Вернуть Dedoc основным во всём API в этой доработке не пытались: нужна парная проверка
на реальных сложных DOCX и воспроизводимая установка.

## Старый протокол и acceptance

Отправленный документ сам не удаляет acceptance. Старый /beta/index позволял
передать клиентский ProcessingResult; отсутствие поля могло возникнуть в таком JSON.
Теперь все /beta/* возвращают 410 и не запускают runtime. Новый API принимает файл
через /v1/documents, сам строит результат и оценивает допуск. Индексатор дополнительно
пересчитывает assess: пропущенная или подставленная accepted_for_indexing=True
не разрешает неразобранное содержимое. Старые публичные process/index/search routes
удалены из OpenAPI; переключателя совместимости нет.
Внутренние методы ядра/CLI сохраняются для приложения и тестов.

Retry использует прежний checkpoint: подходит для сбоя индексации, не для исправленного
парсинга. Новый POST /v1/jobs/{job_id}/reprocess создаёт новое поколение из сохранённого
оригинала и заново выполняет текущий парсер/приёмку. Старый результат неизменяем,
старый активный индекс доступен до готовности нового. Ручной override не добавлен.

## Что значит «обход OCR после Docling закрыт»

Закрыта ошибка допуска: Docling мог заменить OCR-блоки на обычные текстовые,
из-за чего проверка только metadata.extraction переставала видеть происхождение.
Исходное ocr_unverified/визуальное предупреждение теперь тоже вызывает review.
OCR и Docling продолжают работать. Убрана возможность принять их результат без
требуемой проверки, а не возможность распознавания.
Новый CPU-проверяющий движок пока не подключён: см. OCR_VERIFICATION_PLAN.md.
