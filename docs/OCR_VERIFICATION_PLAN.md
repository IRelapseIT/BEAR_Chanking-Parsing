# Дополнительная проверка OCR на CPU

В BEAR подключён PaddleOCR 3.7.0 с PaddlePaddle 3.3.1 и PaddleX 3.7.2 на Windows / CPU.
Используются детектор `PP-OCRv5_mobile_det` и модель `eslav_PP-OCRv5_mobile_rec`.
Оба движка получают один и тот же растр PDFium. Отчёт сохраняет строки,
оценки уверенности, координаты в PDF, размеры растра, преобразование координат,
ревизии и SHA-256 весов. Статус `needs_review` сохраняется для всех OCR-страниц.

## Запуск

В этой копии `config.local.json` уже указывает на `.ocr-venv/Scripts/python.exe`
и `models/paddle-ocr`. Локальный запуск через `scripts/services.py` передаст
настройки при следующем старте API и worker. В других запусках установите
`BEAR_PADDLE_PYTHON` и `BEAR_PADDLE_MODELS`. Окружение создаётся Python 3.12,
зависимости указаны в `requirements-paddle-ocr.txt`. Скачайте
`inference.yml`, `inference.json`, `inference.pdiparams` в одноимённые
подкаталоги моделей. Ревизии проверенной пары указаны в ссылках.
[Детектор](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det/tree/0d63e78e2b680928f6b1747d76a08db6e645efb7),
[распознавание](https://huggingface.co/PaddlePaddle/eslav_PP-OCRv5_mobile_rec/tree/7553801264d3379d8d2e854971989e5e26c22e03).

Для области выделяются до 60 секунд, для задания до 8 областей и 120 секунд
от первой попытки PaddleOCR. Превышение 2 ГиБ RSS дерева процессов отслеживается
опросом, а результат ограничен 2 МиБ и 1024 строками. На ошибке или неоднозначном
сопоставлении действующий текст остаётся доступен для проверки.
Два чтения находятся в `parsed_document.blocks[].metadata.ocr_verification` ответа
`GET /v1/jobs/{job_id}/result`. Если выбрана страница Docling, исходная проверка
остаётся в `primary_ocr_verifications` первого блока страницы.

Для простых таблиц с текстовым слоем добавлено извлечение по координатам слов
под подписью «Таблица N» или «Table N». Оно требует регулярной сетки строк и
колонок и сохраняет координаты ячеек. Статус такой страницы остаётся
`needs_review`, поскольку правильность структуры требует подтверждения.

Для подписи без восстановленной таблицы подключён `PP-DocLayout_plus-L`.
Он сохраняет области с оценками и координатами в `table_layout_candidates`
и ограничен двумя страницами на документ, 45 секундами на страницу и тем же
порогом RAM. При одной обнаруженной области и отсутствии уже разобранных таблиц
координаты получает блок отложенной таблицы. Путь к локальной модели задаёт
`BEAR_PADDLE_LAYOUT_MODEL` или `paddle_layout_model` в `config.local.json`.
Испытание полного PP-StructureV3 на двух PDF сохранено в
`verification/ocr-upgrade/pp-attention.json` и `pp-borderless.json`.
На научной таблице одна из двух эталонных строк совпала, вторая оказалась
смешана с другими ячейками. На безрамочной таблице детектор не нашёл область.
В обработку добавлен детектор областей. HTML, который модель вывела для сложной
таблицы, используется только в сравнении.

Проверочный скрипт `verification/ocr_upgrade_smoke.py` и
`verification/ocr-upgrade/report.json` содержат измерения по двум синтетическим
сканам, размеченной странице приказа и контрольной таблице. Ниже сохранён план
расширенной оценки и допуска.
Для повторной обработки ранее загруженного оригинала после запуска обновлённого
worker используйте `POST /v1/jobs/{job_id}/reprocess`.

## Кандидаты и границы выбора

Текущий путь использует Tesseract. Docling является системой обработки документа;
запуск того же Tesseract через другую обёртку не даёт независимого распознавания.
Нужно фиксировать фактический OCR backend, модель, ревизию и параметры обоих путей.

Первый кандидат для испытаний: PaddleOCR с eslav_PP-OCRv5_mobile_rec.
Официальная карточка указывает восточнославянские языки, английский и числа,
размер модели распознавания 14 MB и CPU-профиль. Детектор, подготовка изображения
и runtime требуют дополнительных ресурсов; 14 MB не является расходом RAM системы.
[Официальные модели PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md).

Альтернатива запуска: RapidOCR с ONNX Runtime. У него есть конвертированные модели
PaddleOCR и выбор runtime/языка. Перед выбором необходимо проверить конкретную
языковую модель, словарь, версию экспорта и совместимость Windows/Python проекта.
Нельзя считать модель по умолчанию русскоязычной без проверки.
[Модели RapidOCR](https://rapidai.github.io/RapidOCRDocs/main/en/model_list/).
Современный пакет называется rapidocr; ONNX Runtime устанавливается отдельно.
[Установка](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/install/).

Предварительная рекомендация: сравнить Tesseract с восточнославянской моделью
PaddleOCR; вариант исполнения через RapidOCR выбрать по реальной установке и тестам,
а не по обещанию меньшего количества зависимостей. Скорость на нашем CPU неизвестна.

## Предлагаемый алгоритм

1. Сохранить исходную страницу, координаты областей, первый OCR и предупреждения.
2. Выделить рискованные области: числа, даты, суммы, низкая confidence, плохой растр,
   неоднозначная ориентация/порядок. Вначале перепроверять все OCR-области малого
   контрольного корпуса; избирательный режим вводить после оценки пропусков.
3. В ограниченном CPU-worker получить второе распознавание исходной области.
   DPI, поворот и deskew записывать; преобразования должны сохранять отображение bbox.
   Не подавать второму движку текст первого как подсказку.
4. Сопоставить области по геометрии, строки по порядку и фрагменты по выравниванию.
   Сравнение набора слов или чисел непригодно: оно не обнаруживает перестановки.
5. Отдельно сравнить числа: знак, разделитель, разряды, дату, валюту, процент и единицу.
   Локаль задаёт допустимую нормализацию; 1,234 без контекста нельзя молча исправлять.
   Для таблиц сравнивать ячейку вместе с заголовком строки/колонки.
6. Проверить целостность: пропавшие области, лишние дубликаты, обрезанные строки,
   расхождения границ и связей с таблицей. Не усреднять конфликтующие значения.
7. Вернуть not_run / agreement / disagreement / insufficient с причинами и обоими
   вариантами. Расхождение, неподтверждённое число или недостающая область -> review.
   Agreement до отдельной валидации политики также не отменяет текущий review.

Первоначальный вариант контракта для расширенной проверки:

```python
def verify_ocr(page_image: bytes, regions: list[OCRRegion],
               primary: list[OCRObservation], limits: VerificationLimits) -> OCRVerification:
    ...
```

OCRRegion: region_id str, page int, bbox tuple[float,float,float,float].
OCRObservation: region_id str, text str, confidence float|None, engine_id str,
model_revision str, bbox tuple[float,float,float,float].
VerificationLimits: max_regions int, max_pixels int, timeout_seconds float,
cpu_threads int, max_memory_bytes int; значения определять после замеров.
OCRVerification: status Literal[not_run,agreement,disagreement,insufficient],
region_results list, reasons list[str], engine_profiles list, elapsed_seconds float.

## Как принять решение по тестам

Нужны исходные картинки и ручная разметка, включая 0/O, 1/l, 3/8, 5/6, минус,
десятичную запятую, мелкий шрифт, размытие, поворот, две колонки и таблицы.
Измерять CER/WER и exact match чисел с контекстом; отдельно долю ошибочных допусков,
долю review, CPU-время и пиковую RAM. Сравнить один OCR, повтор того же OCR и другой
движок. Разделить настройку порогов и отложенную оценку; не подгонять под scan.pdf.
Автоматический допуск обсуждать только по этим данным. Два OCR могут ошибиться одинаково.
