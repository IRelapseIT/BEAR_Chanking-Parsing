# BEAR: документы → BGE-M3 → поиск по чанкам

BEAR сохраняет документ, извлекает текст и таблицы, создаёт проверенные чанки, получает dense-эмбеддинги BGE-M3 и автоматически индексирует принятый результат в Qdrant. Поиск возвращает текст, документ/версию, раздел, страницы и координаты, когда они доступны.

Генерация ответа LLM, reranker и sparse retrieval в конвейер не входят. Это экспериментальная сборка на базе BEAR 0.2.0; промышленная готовность не заявляется.

## Стек

| Компонент | Назначение |
| --- | --- |
| Python 3.12 | Runtime API и фонового worker. |
| FastAPI, Pydantic, Uvicorn | Загрузка, задания, результаты, retry, удаление и поиск. |
| SQLite, файловое хранилище | Оригиналы, checkpoints, очередь, leases и активные поколения. |
| markdown-it-py | Markdown, код и табличная структура. |
| BeautifulSoup, lxml | HTML/HTM: текст, разделы, ссылки и таблицы. |
| ZIP/XML стандартной библиотеки | Нативный DOCX API: абзацы, заголовки, списки, колонтитулы и таблицы. |
| pdfplumber, pypdfium2, Pillow, Tesseract | PDF, OCR сканов, геометрия страниц и областей. |
| Docling 2.148.0, опционально | Резервный разбор проблемных страниц с повторной проверкой. |
| Chonkie 1.7.0, Razdel | Адаптивное, структурное, рекурсивное и семантическое разбиение. |

| EmbeddingPipeline | Подготовка запросов, пакетная векторизация, L2-нормализация и кэш. |

API и Infinity используют **разные окружения**: ядро — NumPy 2.5.4, Infinity — NumPy 1.26.4. Не объединяйте их зависимости без согласования.

## Архитектура

```text
POST /v1/documents → оригинал + durable job
  → worker → ParsingPipeline → ContentBlock[] / канонические ячейки
  → PDF: проверка страниц → при необходимости Docling → повторная проверка
  → чанкинг → проверка токенов, покрытия и source spans → политика приёмки
      accepted → Infinity / BGE-M3 → Qdrant → проверка записи → активация → поиск
      needs_review / rejected → сохранённый результат с причинами
```

Ручной index-вызов после обычной загрузки не нужен. Повтор идентичной загрузки возвращает тот же job ID. При обновлении старое поколение доступно до успешной активации нового; lease и желаемое поколение проверяются при индексации. API и worker разнесены по процессам.

`bear-text-beta/` содержит API, модели, очередь, приёмку, чанкинг и индексирование; `bear-fusion-lab/` — PDF/OCR/Docling, канонические таблицы и родительский контекст. Старый внешний Dedoc-маршрут сохранён для экспериментов Fusion, но штатный DOCX API его не требует.

## Форматы и ограничения

Поддерживаются TXT, Markdown, HTML/HTM, DOCX, PDF с текстом и PDF-сканы. XLSX, PPTX, старый DOC и архивы не заявлены.

DOCX с неподдержанными объектами, сложные PDF, частичное извлечение и OCR могут получить `needs_review`. Порядок колонок PDF определяется эвристически. Покрытие извлечённых блоков чанками не доказывает полноту оригинала; `source_fidelity` остаётся `unverified`.

Чанкинг: target 320 / max 480 токенов; профиль модели — 512. Учитываются контекст и special tokens; скрытое токенное усечение клиентом запрещено. SentenceTransformers внутри Infinity нормализует краевые пробелы модельного входа; исходный текст BEAR сохраняется.

## Установка и запуск

Проверенный локальный путь: Windows, Python 3.12 и PowerShell 7. Веса, окружения и базы в Git не включены.

```powershell
./setup-workflow.ps1 -Python <путь-к-python-3.12.exe> -DownloadQdrant
```

Установщик завершает проверку ошибкой, если модель ещё не подготовлена. Подготовьте её, затем запускайте сервисы:

```powershell
./.venv/Scripts/bear.exe --model-dir models/bge-m3 prepare-model --model bge-m3 --weights
./.venv/Scripts/python.exe scripts/services.py start
./.venv/Scripts/python.exe scripts/services.py status
./.venv/Scripts/python.exe scripts/services.py stop
```

Проверенная ревизия — `5617a9f61b028005a4858fdac845db406aefb181`. Подготовщик нового каталога разрешает текущую ревизию Hugging Face и фиксирует её в manifest. Для точного повторения используйте файлы проверенной ревизии с соответствующим manifest; не смешивайте веса и токенизаторы.

Параметры — `config.local.json`. В переносимой конфигурации Docling выключен пустыми путями: укажите подготовленные `docling_python` и `docling_artifacts`, чтобы включить резерв. Для OCR отдельно установите Tesseract с `eng` и `rus`.

Адреса: [Swagger API](http://127.0.0.1:8002/docs), Infinity `127.0.0.1:7998/v1`, Qdrant `127.0.0.1:6335`. Все слушают localhost. Запуск не останавливает процессы на занятых портах. Остановка проверяет идентичность своих процессов; `state-bge-m3/` и `runtime/qdrant-storage/` сохраняются.

## API

| Endpoint | Действие |
| --- | --- |
| `POST /v1/documents` | Multipart: файл и JSON DocumentContext; возвращает 202 и job ID. |
| `GET /v1/jobs/{id}` | Статус, приёмка, предупреждения и количество чанков. |
| `GET /v1/jobs/{id}/result` | Полный результат с блоками, ячейками и источниками. |
| `POST /v1/jobs/{id}/retry` | Повтор задания после сбоя. |
| `POST /v1/search` | Поиск по query, tenant_id, space_id, top_k. |
| `DELETE /v1/documents/{id}` | Исключение из поиска и очистка векторов. |
| `/live`, `/ready?capability=index` | Liveness и готовность зависимостей. |

Tenant/space-фильтры — контракт доверенного контекста; авторизация и gateway вне этого блока. [Пример загрузки и поиска, настройка и ограничения](docs/WORKFLOW.md).

## Проверки и текущий результат

Последняя проверка 6 ноября 2026: **272 passed, 1 skipped**. Пропущен прежний tensor pooling unit-тест без PyTorch в API-окружении; настоящий BGE-M3 проверен в отдельном Infinity-окружении. Реальные HTTP-проверки включают источники, tenant/space, обновление, retry, удаление, отказы Infinity/Qdrant и перезапуск.

На фиксированном инженерном корпусе автоматически успешны **10/14 — 71,4%**; Recall@5 0,7143, MRR@5 0,6786 по всем случаям. Неудачные/review документы не исключены. **Цель 90% не достигнута**, репрезентативная корпоративная выборка ещё не согласована.
